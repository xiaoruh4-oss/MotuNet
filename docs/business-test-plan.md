# Motu Net 业务场景测试计划

> 历史设计说明：Windows 0.7.6 暂时隐藏“弱网用例”入口，日常测试使用“场景测试”。以下内容记录此前实验流程与数据结构，不代表当前发行版可见操作；已有用户数据仍保留。

这份说明对应本地测试版的“弱网用例 → 按业务场景”模式。它把业务动作与网络条件分开保存：业务场景说明测试人员要做什么，Motu Net 根据测试级别生成要施加的网络条件。这样同一套网络条件可以复用于不同系统，系统专属内容也不会写死在程序中。

## 推荐执行流程

1. 在“详细设置”保存被测系统目标，填写 IP、端口、协议和方向；需要时再填写高级过滤表达式。
2. 先选择“正常对照”并启动一次，确认被测系统有操作、Motu Net 能捕获匹配流量。
3. 进入“弱网用例”，选择“按业务场景”、业务场景和测试对象。
4. 选择冒烟、标准、完整或自定义。自定义模式需要在“选择条件”菜单中至少勾选一个条件。
5. 检查页面生成的用例数量和第一项操作，点击“开始测试”。
6. 按当前项的前置条件、业务操作和重点观察执行；填写实际现象后选择“通过”“不通过”“不适用”或“跳过”。
7. 每项结束后等待网络自动恢复，再进行下一项。中途点击“停止并恢复”会保存已完成项和未执行项。
8. 在“弱网用例”页查看报告保存目录，从该目录打开 JSON/Markdown 报告；需要分享时点击“导出结果”另存 Markdown。

管理员权限、目标 IP/端口和过滤条件是开始真实网络测试的前置条件。计划预览不会拦截流量，只有点击“开始测试”后才会启动网络引擎。

开发运行可在项目目录的 PowerShell 中执行 `.venv\Scripts\python.exe main.py --local-test`。配置和报告写入项目内 `.localdata/local-test`，不会覆盖已安装版本的数据。此参数用于隔离开发数据，不会重新显示 0.7.6 已隐藏的用例入口；当前发行版使用方式见主 README。

## 测试级别

| 级别 | 适用时机 | 条件来源 |
| --- | --- | --- |
| 冒烟 | 每次构建或快速验证 | 场景的 `smoke` 条件，通常包含正常基线、轻度弱网和一次恢复 |
| 标准 | 版本回归 | 场景的 `standard` 条件，必须包含全部冒烟条件 |
| 完整 | 高风险功能或专项测试 | 场景的 `full` 条件，必须包含全部标准条件 |
| 自定义 | 问题复现或临时验证 | 在界面勾选网络条件，不使用场景矩阵 |

一个场景不会自动与所有 15 个网络条件做笛卡尔组合。每个场景按风险配置适用矩阵；无关条件可以保持不执行。需要执行全部业务场景时选择“全部业务场景”，仍会按选定级别为每个场景生成队列。

## 时间规划

每条用例的预计时间包含业务操作、网络现象观察、恢复确认和结果记录。单轮计划预算为 60 分钟：标准弱网模板 9 项预计 50 分钟，通用系统模板 15 项预计 60 分钟；业务场景模式按所选场景和级别逐项累加。页面会显示 `预计 X / 60 分钟`，超过预算时不能开始，建议减少场景、降低级别或改用自定义条件。单个条件的默认预算如下，导入模板时也可以用 `estimated_minutes`（1 到 30 的整数）覆盖。

| 条件 | 分钟 | 条件 | 分钟 |
| --- | ---: | --- | ---: |
| CONN-01 正常网络基线 | 3 | CONN-02 连接中途受扰 | 4 |
| CONN-03 短时断网自动重连 | 4 | CONN-04 手动切换网络恢复 | 4 |
| WEAK-01 弱网加载 | 4 | WEAK-02 低带宽高延迟 | 5 |
| WEAK-03 高丢包重试 | 5 | WEAK-04 长连接中断 | 5 |
| PROTO-01 重复请求幂等 | 4 | PROTO-02 乱序响应一致性 | 4 |
| EXTRA-01 移动网络切换 | 3 | EXTRA-02 后台挂起重连 | 4 |
| EXTRA-03 静态资源降级 | 3 | EXTRA-04 接口超时重试 | 4 |
| EXTRA-05 快速重复点击 | 4 |  |  |

## 内置业务场景

| 场景 | 重点确认 |
| --- | --- |
| 登录与进入系统 | 登录结果只生效一次，失败可重试，恢复后客户端和服务端状态一致 |
| 大厅与页面加载 | 加载反馈、资源失败提示、恢复后的最新数据和页面可用性 |
| 战斗与实时交互 | 实时反馈、断线重连、输入是否重复、双方状态和最终结算 |
| 支付或奖励领取 | 处理中状态、超时重试、重复点击、扣款或发奖次数 |

“新建”或“导入”可以增加例如背包、邮件、排行榜、匹配、下载更新等团队场景。业务场景至少要有前置条件、业务操作、重点观察和通过标准，并为冒烟、标准、完整分别配置网络条件。

## 场景 JSON

可以导入一个场景对象，也可以导入带 `schema_version` 和 `scenes` 的场景文件。文件使用 UTF-8 编码，`schema_version` 当前为 `1`。示例：

```json
{
  "schema_version": 1,
  "scenes": [
    {
      "schema_version": 1,
      "id": "inventory-reward",
      "name": "背包领取奖励",
      "preconditions": "已登录，背包中存在可领取奖励。",
      "steps": "打开背包并领取一次奖励；网络恢复后重新查询背包和奖励记录。",
      "observations": "领取按钮状态、提示文案、奖励数量和恢复后的查询结果。",
      "expected": "奖励最多发放一次；恢复后客户端和服务端数量一致。",
      "network_case_ids": {
        "smoke": ["CONN-01", "WEAK-01", "CONN-03"],
        "standard": ["CONN-01", "WEAK-01", "CONN-03", "WEAK-03", "PROTO-01"],
        "full": ["CONN-01", "WEAK-01", "CONN-03", "WEAK-03", "PROTO-01", "PROTO-02", "EXTRA-04", "EXTRA-05"]
      }
    }
  ]
}
```

`id` 使用小写字母开头，只能包含小写字母、数字、点、下划线和短横线。三个级别的条件必须按冒烟、标准、完整逐级包含，且每级至少有一项。网络条件编号来自 Motu Net 内置目录：

| 编号 | 网络条件 |
| --- | --- |
| `CONN-01` | 正常网络基线 |
| `CONN-02` | 连接中途受扰后继续操作 |
| `CONN-03` | 短时断网自动重连 |
| `CONN-04` | 手动切换网络后的恢复 |
| `WEAK-01` | 弱网加载与发起操作 |
| `WEAK-02` | 低带宽高延迟边界 |
| `WEAK-03` | 高丢包重试与恢复 |
| `WEAK-04` | 长连接场景短时中断 |
| `PROTO-01` | 重复请求幂等 |
| `PROTO-02` | 乱序响应一致性 |
| `EXTRA-01` | 移动网络切换 |
| `EXTRA-02` | 后台挂起后重连 |
| `EXTRA-03` | 静态资源加载降级 |
| `EXTRA-04` | 接口超时与重试 |
| `EXTRA-05` | 快速重复点击防护 |

导入时 Motu Net 会校验字段、编号、级别包含关系和重复 ID。校验失败的文件不会写入业务场景目录；已存在的 ID 也不会被覆盖。

## 结果记录

每条计划项会记录业务场景 ID、网络条件 ID、开始/结束时间、网络配置、引擎统计、实际现象、原因和结果。结果判定边界如下：

- **通过**：业务表现符合通过标准；必须有匹配流量且引擎没有错误。
- **不通过**：业务表现不符合预期；填写实际现象，报告会保留该说明。
- **不适用**：当前系统没有该能力或条件；填写不适用原因。
- **跳过**：本轮暂不执行；填写跳过原因。

网络包数量只能证明过滤和处理是否发生，不能自动证明登录、重连 UI、数据一致性、幂等或最终结算正确。报告中的总体结论以人工业务判定为准。

业务场景文件目录：`%LOCALAPPDATA%\MotuNet\business-scenes`

测试结果目录：`%LOCALAPPDATA%\MotuNet\test-runs`
