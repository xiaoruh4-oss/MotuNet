# 网页游戏定向断网

Windows 0.7.6（2026-11-25）支持对指定服务器执行仅上行、仅下行或双向丢包断网，网卡保持启用。规则以服务器 IP、端口、协议和方向为范围，不会按浏览器标签页或网页路径隔离流量。

## 选择实际业务目标

本地 Cocos 页面由 localhost 提供时，游戏仍可能连接远程登录服、游戏服或 WebSocket 服务。页面入口负责加载内容，不代表游戏请求也发送到这个端口。应从项目配置或浏览器网络面板确认实际业务连接，再填写对应地址。

例如，游戏业务连接为 `wss://game.example.com/game` 时，在“详细设置 → 作用范围”选择“指定网页 / 域名”，填写这个地址，协议选 TCP，端口填 443。`game.example.com` 是示例域名，使用时需替换成自己的测试服务器；若切换测试环境，也需同步修改目标。

地址支持域名、IP、HTTP、HTTPS、WS 和 WSS。端口框非空时优先使用手填值；留空时使用 URL 显式端口，或 HTTP/WS 的默认 80、HTTPS/WSS 及裸域名的默认 443。路径、查询参数不能用于区分网络包。

## 先做持续单向验证

1. 以管理员身份运行 Motu Net，打开游戏并确认正常业务连接。
2. 在“详细设置”填写实际服务器目标，选择对应协议和流量方向。
3. 开启丢包断网，设“延后断网”为 0，“断网持续”为 0（手动停止），关闭循环执行。
4. 返回“场景测试”点击开始，确认顶部进入阻断阶段，再触发一次可追踪的业务请求。
5. 核对服务端收包时间、客户端回复及工具捕获和丢弃计数，在持续阻断期间记录结果。
6. 点击“停止并恢复”，再单独记录重连、补发、重复请求处理和最终业务状态。

| 方向 | 规则匹配的流量 | 验证重点 |
| --- | --- | --- |
| 仅上行 | 客户端发往目标服务器 IP 和端口 | 服务器在阻断期间是否收到新增请求 |
| 仅下行 | 目标服务器 IP 和端口返回客户端 | 服务器可能已处理请求，客户端是否收不到回复 |
| 上行和下行 | 以上两个方向 | 请求、回复、心跳与恢复表现 |

0.7.6 对 localhost 网页目标使用目标服务端口区分上传与下行，因此也可测试真正运行在本机的业务服务。普通“本机回环”范围仍用于整体回环测试；需要单向区分时选择带明确服务端口的“指定网页 / 域名”。

手动停止有助于把阻断与恢复两个阶段分开。完成单向验证后，可设置正常间隔、断网持续时间并开启循环，用于观察重复断开和恢复。

## 判断请求是否送达

浏览器发送记录或 `send()` 成功，只说明客户端尝试发送。TCP 可能先把数据写入操作系统发送缓冲；游戏也可能在断线后把业务请求放入重连队列。恢复网络后，系统重传或游戏重试都可能让服务器收到原先的操作。

因此，恢复后收到业务结果，不能单独证明阻断失效。应将同一请求的客户端标识、服务端实际接收时间与工具阻断区间对应起来。客户端“创建请求”“加入重连队列”等日志不等同于服务端收包记录。

捕获与丢弃计数可以证明匹配数据包被处理，但不能直接证明某个业务请求是否成功。零捕获时应检查目标地址、端口、协议、方向，以及游戏是否切换了其他业务连接。

“停止并恢复”关闭拦截，不会清除操作系统的 TCP 发送缓冲，也不会撤销服务器已经处理的请求。恢复后的补发、重试和幂等处理应单独验收。

## 影响范围

- 单向断网仍通过丢弃该方向数据包实现。TCP 确认包（ACK）也会被影响，因此另一方向可能因确认超时而停滞；不能保证另一方向持续正常，新建连接的握手也可能失败。
- 每次仅运行当前选中的一个目标。页面使用多个独立业务域名时，一个目标不会自动覆盖全部服务。
- 同一服务器 IP、端口和协议上的其他应用或标签页也可能受影响。其他 IP、端口不匹配此规则；共享目标端点时，不能保证 AI 或其他应用完全隔离。
- 每次开始会重新解析域名，运行期间不动态刷新 DNS。服务地址变化后应停止并重新开始。
- 网页定向丢包不触发 Windows 系统离线事件。游戏何时显示重连取决于自身心跳、超时与连接管理逻辑。
- 系统“网卡断网”会影响所选网卡上的所有应用，不能限定网页目标或单独上传、下载方向。
