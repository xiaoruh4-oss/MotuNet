# Motu Net · Weak Network Lab

[下载最新安装包](https://github.com/xiaoruh4-oss/MotuNet/releases/latest) · [全部版本](https://github.com/xiaoruh4-oss/MotuNet/releases)

Motu Net 是面向 Windows 的游戏客户端与服务联调弱网测试工具，通过 Python `ctypes` 适配器调用 WinDivert，在本机网络层对匹配的数据包施加延迟、抖动、丢包、限速等策略。

> **Windows 桌面版安全提示**：启动网络实验会影响本机流量。请只在测试环境和已获授权的设备上使用，实验结束后点击“停止并恢复”并确认状态恢复。程序启动时不会自动开启网络拦截；开始实验时系统可能弹出管理员提权对话框。

## Windows 桌面版环境与安装

- Windows 10/11 x64；需要管理员权限才能打开 WinDivert 驱动。
- Python 3.11+（开发运行）或打包后的 `MotuNet.exe`（用户运行）。
- 仓库已包含 `vendor/windivert/WinDivert.dll`、`WinDivert64.sys` 及其许可证。

开发环境安装：

```powershell
cd NetLab
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py --local-test
```

Windows 0.7.6 暂时隐藏用例入口，默认进入场景测试。顶部显示实际捕获量和丢弃量；未捕获流量时不会认定弱网已影响目标。源码测试可从项目目录运行 `.venv\Scripts\python.exe main.py --local-test`。测试窗口使用项目内的 `.localdata/local-test` 保存配置和报告，可与已安装版本同时打开；点击“以管理员身份重启”仍会保持在本地测试版。

构建 Windows onedir 包：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\tools\build_release.ps1
```

[下载 Windows 0.7.6 安装包](https://github.com/xiaoruh4-oss/MotuNet/releases/download/v0.7.6/MotuNet-0.7.6-Setup-x64.exe)（2026-11-25）。已安装支持在线更新的版本，也可在软件内点击“检查更新”。

## 指定网页/域名弱网（0.7.6）

首页点击“网页定向断网”，或在“详细设置 → 作用范围”选择“指定网页 / 域名”。填写游戏服务器域名、IP，或完整 HTTP(S)/WS(S) 地址；端口留空时使用 URL 显式端口，HTTP/WS 默认 80，HTTPS/WSS 及裸域名默认 443。开始时重新解析域名，只处理本次解析 IP、端口、协议和方向匹配的流量；不匹配的其他 IP / 端口可以继续联网。此模式使用丢包模拟，不禁用网卡，也不触发 Windows 的系统离线事件。

单向验证应填写实际游戏服，例如 `wss://game.example.com/game`，选择 TCP、443 端口及仅上行或仅下行，设置立即开始、手动停止。示例域名需替换成自己的测试服务器。本地 Cocos 页面入口与游戏业务连接可能使用不同地址，拦截页面端口不会自动阻断远程游戏服。目标选择、方向含义和验收步骤见 [网页游戏定向断网说明](docs/web-target.md)。需要重复恢复测试时，可再设置等待时间、断网持续时间并开启循环。

0.7.6 修复了 localhost 网页目标的方向区分：上传指客户端发往目标服务端点，下行指目标服务端点返回客户端。单向断网依然通过丢弃该方向的包实现，网卡保持启用。TCP 确认包也受影响，因此另一方向可能因确认超时而停滞；这不等于过滤器改成双向。浏览器发送记录、`send()` 成功或恢复后收到奖励，都不能单独证明请求在断网期间送达。应记录服务端实际收到请求的时间，并与顶部的阻断阶段对照。停止后操作系统可能重传，游戏也可能重试；“停止并恢复”不会撤销已经排队的业务请求。

每次只执行当前选中的一个目标，创建多个场景不会同时启动。网页游戏可能连接登录、资源、CDN、统计等多个服务；同一目标 IP、端口上的其他服务也会受影响，不能保证 AI 与游戏共用 IP / 端口时完全隔离。HTTPS URL 路径不能在包层单独匹配。DNS 仅在每次开始时解析，循环期间不动态更新；长测发现服务地址变化时，应停止后重新开始。系统“网卡断网”仍影响整张所选网卡，不能按网页过滤。

可直接把安装包发给同事。安装向导显示实际安装目录，可点击“浏览”修改；检测到原安装记录时默认沿用原目录，确认后覆盖升级。完整程序目录位于 `staging/MotuNet`。真实网络测试需先点击“以管理员身份重启”，再点击“开始测试”。

常规升级会跳过内容相同的网络驱动，避免重复替换导致重启电脑。若未来驱动本身发生变化且仍被占用，安装器会提示必要的重启。

## 使用方法

1. 在“场景测试”页点击常用场景卡，或从下拉框选择全部内置及已保存场景，确认上传/下载方向。选择本身不会启动网络拦截。
2. 如需修改参数，进入“详细设置”配置 IP、端口、协议（TCP/UDP）、方向（入站/出站/双向）、localhost 或高级 WinDivert filter。高级 filter 仅允许经过语法校验的表达式，并自动排除 `impostor` 数据包。
3. 以管理员身份运行后，返回首页点击“开始测试”。顶部显示运行状态；收发包、丢弃、重复、乱序、队列和错误计数在“测试记录”页查看。
4. 可设置定时停止（秒）；到时引擎自动停止。随时点击“停止并恢复”可立即清空队列并关闭句柄。
5. 运行中选择其他场景后，点击“切换并启动”会先恢复当前网络，再启动新场景。当前选中参数已生效时按钮显示“当前场景运行中”，不可重复启动；停止后可重新开始。顶部始终显示实际运行的场景和阶段。

## 在线更新

- 0.5.0 起，程序启动后会后台检查 GitHub 最新稳定版；左下角“检查更新”可随时手动检查。
- 发现新版本后显示更新说明。选择“下载并更新”会先停止当前测试并恢复网络，下载并校验安装包，再打开安装向导；“稍后”保持当前版本。
- 自动检查失败不会打断正常使用。正在测试时，自动发现新版会等测试结束再提示；下载可取消，失败后可重试。
- 公开安装包无需 GitHub 账号，但网络须能访问 GitHub 及其文件下载服务。
- 0.4.x 不具备更新检查功能，需手动安装一次 0.5.0 或更高版本。用户场景和皮肤保存在安装目录外，升级会保留。
- 发布与开发流程见 [GitHub 发布说明](docs/github-release.md)。

## 皮肤与场景库

- 左下角“皮肤”按钮可选择蓝白、深色、青绿，立即生效并记住选择。切换皮肤不会改变正在运行的测试。
- “新建场景”：输入名称，从正常网络参数开始创建，调整后点击“保存修改”。
- “另存为新场景”：复制当前全部参数（包含 IP、端口、方向和断网时间），输入新名称保存，保留原场景。
- 已保存的自定义场景会出现在“详细设置”的场景库和首页下拉框，重开软件仍可选择；“保存修改”只更新选中的自定义场景。内置场景改动需另存，内置模板会保留。
- “删除场景”：在详细设置选中已保存的自定义场景，点击删除按钮并确认。删除后回到“正常对照”，不会启动测试；取消会保留场景和当前修改。内置场景不可删除，测试或更新期间删除按钮暂不可用。
- “导入场景”载入 JSON 后可直接测试，也可保存到场景库；“导出场景”用于分享给同事。取消名称输入或名称重复均不会覆盖原场景。
- 场景保存在 `%LOCALAPPDATA%\MotuNet\scenarios`，皮肤偏好保存在同目录下的 `theme_settings.json`；升级不会清除这些用户数据。
- 基础区显示带宽、延迟、丢包；“高级选项”内有重复、乱序和短时断网，选择含这些条件的场景会自动展开。

## 0.7.3 本机验证

本机管理员权限下完成专用回环端口测试：UDP 0% 丢包时 200/200 到达；20% 时 400 包丢弃 79（19.75%）；100% 时 200 包全部丢弃。TCP 100% 时阻断，停止后重传并恢复。另检查延迟、抖动、限速、重复包、乱序暂存与延后断网自动恢复。全部专用拦截已停止；这些结果不代替具体游戏服务器或网卡链路验收。

## Windows 系统网卡断网（0.7.4）

首页点击“网卡断网 · 系统禁用”，选择当前以太网或 Wi-Fi，设置“延后断网”和“断网持续”，返回场景测试页开始。系统会真正禁用所选适配器，与 Windows 高级网络设置的“禁用”效果对应；未选中的其他网卡仍可联网。

网卡模式影响该网卡所有应用，不能限定 IP、端口或流量方向；本版单次持续 1–300 秒，结束或点击停止后重新启用。只接管原本启用的物理网卡。禁用前先保存恢复记录、登记系统恢复任务；独立进程在程序退出时尝试恢复，恢复失败会保留重试入口，下次管理员启动也会检查未完成的恢复。网卡重新启用后，Wi-Fi 关联与游戏重连还可能需要时间。原“短时断网/延迟断网”及已保存场景仍使用丢包模拟，避免升级改变原测试含义。

## Windows 桌面版支持范围

- 延迟与随机抖动（毫秒）
- 丢包率、短时 blackout（等效 100% 丢弃）
- 带宽限制（KiB/s，按方向排队）
- 数据包重复率、乱序延迟
- IP/域名/端口/协议/方向/localhost/高级 filter 匹配
- 定时停止、运行统计、操作日志、本地 JSON 配置和预设场景

## Windows 桌面版限制与已知问题

- Windows 桌面引擎仅支持 Windows x64；依赖 WinDivert 驱动，非管理员环境无法完成真实端到端拦截。最终真实测试状态以测试记录为准，本 README 不宣称已完成。
- Windows 桌面引擎不能按进程或浏览器标签页筛选，也不能直接控制手机或其他设备。网页目标使用服务器 IP、端口和方向匹配，影响范围见 [网页游戏定向断网说明](docs/web-target.md)。
- TCP 重置（RST）列入后续路线，首版未实现，界面和文档不应将其视为已支持功能。
- 日志是本机操作记录，不是防篡改的企业审计系统。
- 复杂 filter、IPv6、驱动版本兼容性可能因系统策略而异；请先用“正常对照”场景验证链路。

## 延迟断网

勾选“完全断网”后设置“延后断网”和“断网持续”：开始测试后先保持网络正常 N 秒，再对匹配流量断网 M 秒，结束后自动恢复。将“延后断网”设为 0 即立即断网；仅在立即断网时允许将“断网持续”设为 0，表示手动停止。等待和断网阶段的剩余时间会显示在状态区，点击“停止并恢复”可提前结束。

勾选“循环执行”后，自动重复“正常联网 N 秒 → 断网 M 秒 → 恢复网络”，直到点击“停止并恢复”。循环模式下两段时间均需至少 1 秒；例如延后 10 秒、持续 5 秒，会每轮联网 10 秒、断网 5 秒。顶部显示当前轮次和阶段倒计时。循环开关默认关闭，可随自定义场景保存、导入和导出。循环模式不使用普通测试的“自动恢复”时长，停止、切换场景或关闭窗口会结束循环并恢复网络。
